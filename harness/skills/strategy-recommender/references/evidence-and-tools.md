# 证据与工具合同

## 已上线策略：只作识别索引

下表反映本次接入的五套策略，不作为上线状态和参数的静态白名单。以 `list_investment_strategies` 当次返回为准。

| ID | 名称 | 需要理解的差异 |
| --- | --- | --- |
| rsi-profit | 分批低吸目标止盈 | 弱势分批投入，目标退出；等待和持续下跌风险，不是保本止盈 |
| nav-swing | 净值波动低吸高抛 | 相对区间与回稳/转弱规则；可能踏空和反复观察 |
| trend-strength | 趋势强弱 | 趋势确认、周期次数限制；快速反转时存在滞后 |
| gem-valuation | 创业板估值百分位 | 专属指数暴露、估值及现金池；倍数投入与新增资金需预算核对 |
| industry-trend | 行业基金趋势轮动 | 多基金池、行业切换、月度复核；不能当作单基金低频定投 |

规则类型不是风险等级。低吸不能保证低风险，现金池不能保证不亏，按月检查不等于每月只发生一笔交易。

## 推荐依据的层次

1. 目录合同：可说明规则、支持参数、数据要求与代价，不能提供业绩数字。
2. 已核验默认样本：可展示来源、标的、区间和真实指标，只支持该样本的历史观察，不能称作用户专属结果。
3. 用户条件回测：调用 `run_investment_backtest` 并检查状态、缺失项/校验信息后解释；记录策略版本、基金、参数、区间、资金流、费用和结果引用。
4. 实际交易：只来自授权账户查询；不能用上述回测或本地草稿冒充实际执行。

同一指标仅在含义、区间、样本和资金口径足够一致时排序。尤其要检查累计涨幅、资金加权收益、投入/期末金额、收益金额是否同一种口径。最大回撤符号按真实定义展示。模拟盈利金额受投入影响，不能直接当“更好”。

## 实际可用动作

- `list_investment_strategies`：获取目录及支持参数。不要为回答目录规则调用账户工具。
- `run_investment_backtest(strategyId, code, params)`：确定性运行；只传 schema 接受的字段。当前接口需要 `code`，组合策略如何处理由引擎合同决定；用户未选单基金时不得偷偷把默认样本当用户选择。目录 defaultFundCode 可在明确标注为样本演示时使用。
- `save_strategy_variant`：保存受支持的配置变体，不保存任意算法，不创建订单，不代表跟踪开启。先给用户查看修改项和影响；已有明确保存授权无需重复确认同一件事。
- `create_strategy`：另一套模板的本地计划草稿接口。其 templateId 与投资策略 ID 不保证相同；没有明确映射时禁止直接套用。客户端回测页的“保存计划”走专用页面流程；没有对应工具时引导用户在那里完成。
- `request_user_input`：按运行时提供的真实 schema 调用；若不可用，用一句问题继续对话，不编造按钮已经出现。
- `[[STRATEGY_CANDIDATES:...]]`：现有客户端可渲染候选引用。不要输出不存在的其他控制标记。普通文字“已筛选”“已打开对比”“已保存”不产生页面操作，只在工具或真实 UI 确认后描述操作成功。

## 自建草稿应有哪些字段

仅在用户明确想自建且超出现有合同后，逐步整理：草稿名称、目标、标的范围、指标和数据来源、计算周期、触发阈值、买卖动作、单次金额/仓位、周期资金上限、冲突信号优先级、退出规则、费用假设、待补字段、当前不可执行的原因。

没有指标源、实现或可回测接口时，状态为“待实现/待验证”。不要推荐安装外部交易插件，不编写或运行任意策略代码，不把草稿声称为已上线策略。用户未要求自建时，无候选也不能自动进入此路径。
