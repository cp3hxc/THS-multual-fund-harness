# 苏维客户端「找策略」高保真设计方案

## 1. 产品场景与演示边界

使用者是希望用基金或 ETF 策略完成个人目标的普通投资者。他已经知道自己每月可投入 2,000 元，预计持有 3 年，希望少操作，却尚未明确能承受多大阶段亏损。首屏直接呈现这个探索过程：已确认偏好、当前筛选结果、策略证据和苏维的下一问同时可见。

本目录是可操作的**高保真交互演示**。策略名称用于说明产品流程；曲线、收益、回撤、计划记录和时间均为演示数据，页面逐处标识。对话由本地情境脚本驱动，没有接入真实模型、实时行情、账户或交易。保存的演示计划只存于浏览器本地，不会发起真实申购。

## 2. 1440 × 960 基准布局

| 区域 | 建议宽度 | 作用 |
| --- | ---: | --- |
| 左侧主导航 | 210 px | 只放一级工作区入口、新探索和最近任务 |
| 策略工作区 | 自适应，约 835 px | 发现、详情、对比、计划草稿与追踪 |
| 分隔拖柄 | 5 px | 鼠标拖动或方向键调整对话宽度 |
| 右侧苏维对话 | 初始 390 px，可在 310–560 px 调整 | 讨论、引用对象、解释变化、产出操作 |

对话收起后保留 56 px 任务条和恢复按钮，工作区自动获得更多宽度。工作区和对话区独立滚动。窗口变窄时左侧导航折叠为图标，策略卡片改为单列。

视觉上，左侧与对话区采用深绿色石墨色，工作区用浅色高对比底色。绿色表示已确认、可执行的下一步；浅琥珀色表示待确认或需要注意的限制。历史收益与回撤不以夸张色彩诱导选择。所有页面标题、按钮和解释均使用中文。

## 3. 共同任务状态

工作区与对话共享以下对象。它们应由同一个前端状态层管理，服务端保存时带版本号。

| 对象 | 必要字段 | 页面与对话的协作方式 |
| --- | --- | --- |
| 探索任务 | 任务 ID、消息、偏好、当前视图、列表位置 | 返回列表、切换标签或收起对话时保留 |
| 偏好 | 值、来源、确认状态、更新时间 | 用户编辑立即生效；AI 推测先标待确认 |
| 策略 | 策略 ID、规则版本、适用范围、指标与口径 | 卡片、详情、对比和对话引用同一个版本 |
| 对比集合 | 最多 3 个策略 ID、统一统计区间 | 卡片加入与自然语言比较进入同一视图 |
| 计划草稿 | 策略版本、预算、频率、标的、规则、提醒 | 页面直接编辑与对话修改更新同一草稿 |
| 已保存计划 | 计划 ID、版本、状态、事件、执行记录 | 独立于探索任务，可重新打开和修订 |
| 对话上下文 | 当前策略 ID 列表或计划 ID | 在输入框上方显式展示，可移除和切换 |

点击另一张策略卡片只切换“当前查看对象”，**不发送提问**。点击“让苏维解读”或发送消息，才开始分析。策略探索与每份计划应有独立对话记录；新建探索不删除已有计划及其历史。

## 4. 页面与关键状态

### 4.1 发现策略

首屏顺序：标题与副文案 → 已有计划的紧凑进展条 → 当前偏好 → 推荐依据 → 搜索与收藏 → 4 张双列策略卡片。卡片展示人话规则、适用场景、投入节奏、建议关注周期、示例曲线、收益与最大回撤、数据区间和个性化理由。主要操作为“了解策略”，其次是“加入对比”；收藏为图标按钮。

偏好不足时标题为“策略精选”。确认预算、期限和操作偏好后改为“根据你的偏好筛选”，逐项说明使用了哪些条件。未知亏损承受意愿保持待确认，不显示虚构的匹配百分比。筛选后无结果时展示发生冲突的条件和调整入口，不自动放宽条件。

### 4.2 策略详情与苏维解读

中间区从上到下呈现：一句话规则、分步执行规则、历史表现与回撤、适合与可能不适合的人、生成计划按钮。规则和图表各有情境入口。点击“解释这段回撤”时，正式产品应把选中区间、数据来源、基金或指数标识放进对话上下文；不能只发“解释回撤”四个字。返回列表要恢复原有滚动位置。

### 4.3 策略对比

底部轻量对比栏展示已选对象，最多 3 个。表格使用相同时间区间、投入假设及费用口径比较收益、回撤、投入频率、资金要求、使用场景。若真实策略的数据区间无法对齐，单元格显示“不可比”及原因。对话中的“比较前两个”打开同一个对比视图，苏维解释取舍，不替用户作决定。

### 4.4 计划草稿与修改确认

草稿字段：名称、关联策略和版本、投资目标、期限、每月总预算、投入频率、每期金额、候选标的、触发规则与提醒方式。缺失项显式显示“待选择”或“待确认”。页面可直接编辑；对话修改将受影响字段高亮，展示修改前后值并支持撤销。

“改成每两周一次”时，维持每月总预算不变，再把每期金额按一年约 26 期折算。正式产品须说明实际扣款日和金额舍入方式。保存按钮为“保存并开启追踪”；如是在修订旧计划，按钮为“确认并更新计划”，生成新版本并保留原版本。

### 4.5 我的计划与事件分析

顶部统计追踪中数量、待处理事件和更新时间。每行先给下一步：状态、已记录投入、计划进度、最新事件和下次检查，提供“查看计划”“问苏维”。详情展示当前规则、执行记录、进度图和事件时间线。进度图不能被标成投资收益。

提醒以有意义的事件为单位。例如“本期投入日期已到，尚未记录执行”，允许查看原因、记录执行或稍后提醒。尚未记录不等于未成交。用户询问回撤、跳过投入或提前用钱时，回答应引用计划版本、实际可用的数据和事件记录；不能凭空给出实盘表现。修改必须先生成草稿，经确认后更新版本。

## 5. 对话行为与反馈

- 开场只问最影响选择的 1–2 个问题；首屏下一问是阶段亏损承受意愿。
- 对话输出采用“简短解释 + 可操作对象”。推荐策略在对话内显示轻量引用，完整操作保留在工作区。
- 用户直接编辑偏好后立即刷新工作区；下一轮对话读取最新已确认条件。
- 当用户同时要求更高收益和绝不亏损，先解释冲突，请用户排序目标，不制造符合条件的推荐。
- AI 分析时显示具体阶段文案，如“正在按期限与投入节奏筛选”，允许取消。失败时保留上次结果并提供重试。
- 收起苏维后显示当前任务摘要和恢复入口；拖柄支持鼠标和键盘。

## 6. 数据契约与上线要求

正式接入时，策略卡片需要：策略 ID、版本、规则摘要、适用标的、投入规则、风险揭示、数据来源、截止时间、回测起止区间、费用假设、比较基准、收益及最大回撤。曲线点必须与指标来自同一回测运行；旧数据失效后需要重新计算或展示“暂不可判断”。

计划追踪应区分三个来源：**策略模拟结果**、**用户手动记录的执行**、**交易系统确认的订单**。它们在 UI、数据字段和对话引用中不可混用。保存计划仅创建追踪规则；真实买卖需进入独立订单确认流程。

本原型保留了本地交互状态，方便同事评估整体体验。生产实现还需接入模型服务、策略引擎、数据来源、持久化任务与通知服务；这些能力不能由页面演示数据代替。

## 7. 建议的走查路径

1. 在首屏看偏好与苏维追问，点“了解策略”，看详情与图表引用。
2. 返回列表，将两张策略加入对比；试用“问苏维如何取舍”。
3. 生成计划草稿，在对话输入“改成每两周一次”，查看金额折算、前后差异与撤销。
4. 保存并开启追踪，进入计划详情；查看事件、记录执行，再输入“半年后可能要用这笔钱”查看调整草稿。
5. 收起对话、切换“发现策略／我的计划”、拖动分隔线，确认任务状态仍在。
