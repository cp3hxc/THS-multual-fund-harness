# SUVI 推荐策略 Skill 与探索引导

更新：2026-09-28

## 产品决策

默认通过当前已上线策略满足需求。推荐逻辑承担“理解条件、识别冲突、选择候选、解释取舍、推进验证”；具体计算由现有策略引擎承担。

| 用户意图 | 交付对象 | 边界 |
| --- | --- | --- |
| 找适合自己的策略 | 当前目录内的候选与选择依据 | 可以没有合适候选，不强推 |
| 调整金额/频率/支持阈值 | 已有策略配置变体 | 不改变原算法语义，不默增预算 |
| 明确提出指标/买卖规则并想自建 | 自建规则草稿 | 当前引擎不执行新算法，不能声称已回测或已上线 |

## 每个环节

| 环节 | 用户动作 | AI 下一步 | 页面承接 |
| --- | --- | --- | --- |
| 开始 | 自由输入，或从收益目标、可承受回撤、投资方向、用钱时间选择切入 | 复用已说条件，只问最影响下一步的一项 | 主页面对话，首问有可点击答案与自由输入 |
| 形成条件 | 回答期限/资金/风险/操作问题 | 区分确认信息、未知与建议；识别冲突 | 对话内问题；可以填“不确定” |
| 候选 | 看 AI 给出的 1–3 个候选 | 每个给符合点、代价与待验证项 | 真实策略引用，查看规则与回测、加入对比 |
| 理解与比较 | 问规则、回撤、比较两个 | 围绕具体对象回答，核对指标口径 | 现有策略详情与对比功能 |
| 个人条件验证 | 选策略/基金，确认回测条件 | 映射支持参数，核对预算，调用确定性回测 | 工具返回结果；缺数据保留已有内容 |
| 调整 | 修改已支持参数 | 显示原值、新值及影响 | 对话确认后保存配置版本；不是任意代码编辑 |
| 保存计划 | 用户在回测页明确保存 | 区分配置版本与计划草稿 | 沿用现有保存计划入口，不宣称已经自动监控或买入 |
| 自建 | 明确给出超出合同的指标规则 | 列规则、待补项和缺失实现 | 目前为会话内草稿；没有新算法执行功能 |

## 16 类问法

完整分流、提问示例、反例与复核场景在：

- `harness/skills/strategy-recommender/SKILL.md`：核心决策规则。
- `harness/skills/strategy-recommender/references/journeys.md`：问法 → 追问 → 下一步，以及跨阶段示例。
- `harness/skills/strategy-recommender/references/evidence-and-tools.md`：上线目录识别、回测证据、保存能力、自建边界。

不按问法硬编码推荐某一策略。例如“少操作”不能直接对应趋势策略；需要区分检查次数和交易次数，再核对真实规则。

## 本次接入

- `desktop/main.js` 将 Skill 路径传给统一 Agent 运行时。
- `desktop/agent-runtime.js` 加载核心文件和两份引用，作为新建/恢复会话的开发者指令。订阅和自备 API 共用该入口，不依赖模型自行读取本地文件。
- 桌面消息入口补充长度受限的探索上下文、对比对象和核验样本摘要。表单偏好仍作为待核对输入，不冒充用户确认。
- 首问按钮只发送真实选择，例如“我能接受的回撤是 10% 左右。”流程控制不再伪装成用户说的话。
- 候选策略的“查看规则与回测”直接打开详情；当前正在对话时也能切换到策略工作区。
- 后续选择题支持自行填写；用户不必受限于 AI 给出的选项。
- 从最近对话恢复时也可渲染策略候选引用，不暴露机器标记。
- Windows/macOS 共用资源打包清单已加入完整 Skill 目录。

该 Skill 是客户端推荐编排层，不是面向外部 Agent 分发的单策略执行包。参考既有策略规范中的真实规则、参数合同、数据来源和可追溯原则；不套用“安装后自动开场”“安装交易 Skill”“自动创建定时任务”等外部宿主流程。

## 当前限制与验收

代码接入已完成，需要重启客户端后新建或恢复会话才能加载新的运行时指令。本次未运行模型端到端测试、Windows/macOS 安装包构建或自动化测试，不能视作全部验收通过。

后续用 journeys.md 的复核场景实际走通：不重复问、拒绝补充仍可探索、无合适候选、无账户授权、回测失败、预算变化、明确新规则、旧会话恢复。重点确认真实模型遵循规则，且页面对象和回答一致。

当前探索条件保存在会话上下文，尚不是独立的跨会话偏好数据库；自建草稿尚无持久化编辑器和执行引擎；计划监控、通知和真实交易不能由这份 Skill 自动补出。
